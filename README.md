# 互动反馈采用凭证

内容团队记录直播、短剧和网文反馈如何影响后续创作，并抵御操纵。

核心主张：**观众反馈可以成为创作依据，但热度本身不是创作命令。** 每一次"因为观众……所以我们改了"都必须能出示一条完整证据链：互动规则（开始前锁定）→ 原始计票 → 调整台账 → 计票运行（含规则指纹）→ 人工编辑决定 → 创作者回应 → 内容版本。

## 事件样例

`fixtures/audience_feedback.json` 是一条脱敏但字段完整的业务样例：第 201 集直播投票"是否删除苏晚支线"，直播现场原始结果为删除 8 : 保留 3，团队据此临时删掉了人物支线镜头；付费观众质疑高声量来自刷票。正式重算时：

- 跨平台同人的两票去重（保留截止前最后一票）；
- 已退款订单对应票、游客零权重票、主动撤票被剔除；
- 同设备/同支付手段的 4 票协同刷票簇整体排除；
- 截止后渠道补传的迟到票单列，不进任何正式口径。

调整后有效结果为 **删除 0 : 保留 3**——高声量确系操纵与失效资格。已发布的 `ep-201-v1` 不可修改，纠正只能进入新版本 `ep-202`。网文评论区对续篇的讨论不构成承诺；只有登记进 `subscriber_promises` 的表述才有可核验状态。

## 数据合同

- `schema_version: 2`，保留 v1 全部既有标识（`record_id` / `domain` / `occurred_at` / `revision` / `source`）及其含义；v1→v2 仅追加结构，旧代码忽略新字段即可，迁移说明记录在样例的 `migration` 字段中。
- 记录读取后递归冻结：所有"重算"都返回新对象并追加新条目，禁止原地改写历史。

主要结构：

| 结构 | 作用 |
| --- | --- |
| `interactions` | 互动本身；开始前锁定资格快照、权重表、截止时间、编辑不可让渡边界，存规则指纹 `rules_hash` |
| `identities` / `coordination_clusters` | 跨平台账号合并依据、退款记录、协同刷票簇信号与证据 |
| `votes` / `comments` / `support_tickets` | 原始互动事件，带平台、身份与时间 |
| `adjustments_ledger` | 每一条去重、退款、零权重、撤票、协同异常、迟到处置的依据（规则条款 + 证据 + 决定人 + 决定时间） |
| `tally_runs` | 追加式计票运行；`raw`（原始口径）与 `adjusted`（剔除异常口径）并排；新运行通过 `supersedes` 取代旧运行 |
| `content_units` / `content_changes` / `editorial_decisions` / `creator_responses` | 内容版本（含已发布指纹与私人草稿访问名单）、变化、人工决定与采用/部分采用/拒绝理由 |
| `comment_themes` / `opinion_clusters` | 评论主题与跨入口同一意见聚类（弹幕、评论、工单归并） |
| `subscriber_promises` | 对订阅者的正式承诺，状态迁移追加留痕，履行必须附可核验证据 |
| `reward_settlements` | 贡献奖励；计酬单位是意见聚类，同一意见跨入口只计酬一次 |

## 源代码模块

- `src/contracts.js` — 合同读取与深度冻结（兼容 v1/v2）
- `src/rules.js` — 规则开始前锁定校验、规则指纹、不可让渡边界判断
- `src/ledger.js` — 调整台账校验、票的处置归类（有效/排除/迟到）、权重解析
- `src/tally.js` — 原始/调整双口径计票、追加式计票运行、已发布版本不可变校验
- `src/provenance.js` — 双口径并排对比、内容变化依据链追溯、"热度不是命令"合规校验
- `src/responses.js` — 创作者回应校验、私人草稿访问控制、承诺状态机与订阅者核验视图
- `src/rewards.js` — 意见聚类与奖励结算（重复申请只能生成 `denied_duplicate`）

## 关键不变量

1. 资格、权重、截止时间、编辑不可让渡边界在互动开始前锁定；规则指纹事后可验，篡改即失配。
2. 跨平台合并、撤票、退款、协同异常、迟到数据，每种处置都必须留下规则条款、证据、决定人、决定时间；一票不得被重复排除。
3. 迟到票不进任何正式计票口径，单列留档；即使台账漏标，晚于截止时间也自动归入迟到通道。
4. 计票运行追加保存：重算产生新运行并通过 `supersedes` 取代旧运行，旧运行数字与已发布章节/镜头指纹永不改变。
5. 内容变化必须挂人工编辑决定并能追溯到具体计票运行与规则版本；仅依据已被取代的临时结果而无纠正记录，不合规。
6. 创作者决定只允许 `adopted` / `partially_adopted` / `rejected` 且必须给理由；`private_draft` 仅对名单内编辑开放。
7. 讨论不自动构成承诺；正式承诺状态可由订阅者核验，履行必须附证据。
8. 奖励按意见聚类结算，同一意见无论出现在多少入口只计酬一次。
