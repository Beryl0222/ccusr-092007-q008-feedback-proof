# 互动反馈采用凭证

内容团队记录直播、短剧和网文反馈如何影响后续创作，并抵御操纵：

- **规则先冻结**：每场互动在开始前固定参与资格、权重、开始/截止时间与编辑不可让渡的边界（观众无否决权、热度不自动构成创作命令）；
- **反馈可关联**：投票、评论主题、创作者回应都能关联到具体章节/镜头版本；
- **异常有依据**：跨平台账号合并、撤票、退款用户、协同刷票、迟到数据全部留处理依据；
- **结果可对照**：原始计票与排除异常后的计票以只追加快照并排保存，重算不改已发布成片；
- **变化可追溯**：创作者记录采用 / 部分采用 / 拒绝及理由，每个内容变化都能追溯到实际依据的计票版本；
- **承诺可核验**：对订阅者的正式承诺有状态历史与履行凭证，评论区讨论不构成承诺；私人草稿仅授权编辑可见；
- **计酬不重复**：同一意见即使在多个入口出现，也凭意见指纹只计酬一次。

`fixtures/audience_feedback.json` 是一条脱敏业务样例（schema_version=2），复现了
“直播投票删支线 → 付费观众质疑刷票 → 排查后排他翻转 → 新版本恢复支线”的完整链路。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `src/contracts.js` | v1/v2 数据合同、v1→v2 迁移、规则冻结、全量校验 |
| `src/feedback.js` | 合并/投票/撤票/退款/评论/异常/迟到、raw 与 adjusted 计票、并排差异、主题归纳 |
| `src/editorial.js` | 内容版本、创作决定与溯源、承诺状态、私人草稿权限、奖励去重结算 |
| `scripts/generate_sample.mjs` | 通过公开 API 生成业务样例并回写 fixture |
| `docs/SCHEMA_V2_MIGRATION.md` | v1→v2 迁移说明与规则保证对照表 |

源代码只定义读取样例所需的合同与处理流程；后续新增状态必须先改合同、说明迁移方式。

## 本地检查

```bash
npm test                 # 运行全部合同与业务规则测试
node scripts/generate_sample.mjs   # 用当前合同重新生成脱敏样例
```
